# Text Console · 留言系统 UI 重构版

在原 **162100 留言本** 的数据结构和管理功能上改造，保留原项目版权声明。此版本是外观及文本处理升级，并非更换数据库。

## 新功能

- 暗色简洁科技风、移动端自适应：浏览、新建、管理设置、维护页面统一视觉。
- 编辑器右下角提供 **一键清空** 和 **一键粘贴**，粘贴插入在光标选区位置。
- 留言卡片及管理员回复提供 **一键复制**，复制的是原文，不是 HTML 标签。
- 前后端均已移除“必须包含中文”的检查；仅拒绝空白内容，允许单个英文字母、数字、斜杠等。
- 采用 UTF-8 无损存储新文本：保留 `\\`、`/`、`|`、`&`、引号、HTML 文本、行首/行尾空格、多空格、制表符和多行换行。
- 新留言在原数据库中采用 `V2JSON:` + Base64(JSON) 编码，管理员新回复采用 `V2REPLY:`，浏览时安全解码、转义显示；无需改变数据库索引及存储格式。
- 可读取原有 GB2312/GBK 留言并按旧规则显示旧记录；**不会在加载时改写** `data/file.php`、`data/index.txt`、`data/space.txt`。
- 内容显示不再强制固定高度截断。
- **发布成功后自动结束编辑页面**，短暂显示成功状态后返回留言列表，定位并高亮刚刚提交的那一条；分页、排序和审核模式同样支持。提交失败不会跳走，保留输入内容。

## 部署说明（重要）

1. **先完整备份线上站点**（包括 `config.php`、`data/`、`inc/badword.php`）。建议在测试环境验证，再部署线上。
2. 推荐使用提供的 `txt-modern-code-only.zip` **代码更新包**覆盖程序文件。它不包含 `config.php`、`data/`、`__temp__/` 和用户自定义禁词表，避免覆盖线上密码、配置或已有留言。
3. 原站点 `config.php` 若仍是 GB2312/GBK 编码，**可以保留不动**，新版运行时会自动将站点名称和分类转换为 UTF-8；**无需重新保存管理员密码**。原 `inc/badword.php` 也可以保留。
4. **切勿将 `data/file.php` 整体转换成 UTF-8！** 它是按字节偏移量索引的文本数据库，转码会导致老索引失效。也不要用上传压缩包内的历史 `data/` 覆盖线上最新数据。
5. `txt-modern-full.zip` 是包含上传时原有数据、设置和资源的完整工程快照，仅适合新环境部署或作为备份对照；线上更新应优先使用代码更新包。
6. PHP 需启用 `iconv` 和 `json` 扩展，建议 PHP 7.4 或更新版本；网页建议使用 HTTPS。
7. 直接访问 `index.php` 浏览、`write.php` 发布；旧的管理员功能仍从原入口进入。

## 粘贴权限说明

- “一键粘贴”依赖浏览器 `navigator.clipboard.readText()`，一般要求 **HTTPS、localhost 或可信安全上下文**，浏览器可能需要用户同意权限。
- 如果浏览器阻止读取剪贴板，编辑框会获得焦点，请使用 **Ctrl+V** 或 **⌘V**；这是浏览器安全限制，不能由服务器绕过。
- “一键复制”优先使用浏览器剪贴板 API，并提供旧式复制回退。

## 兼容性与注意事项

- **旧数据本身已经丢失的字符无法自动还原。** 新版只保证此后输入并保存的内容无损。
- 新版默认仅检查内容不为空或全空白；正文仍有 `WORD_SIZE` 个 Unicode 字符的上限（默认 9999），标题有 `SUBJ_SIZE` 个字符的上限（默认 100）。
- 所有用户文本在页面展示前进行 HTML 转义，防止直接执行粘贴的 HTML/JS。
- 若使用旧版程序同时写入同一数据库，旧版不认识新记录的 `V2JSON:` 编码，**请不要混合运行新旧程序版本**。
- 当前提供的是源码重构与服务器端功能验证；不同浏览器的系统剪贴板授权行为需在实际部署站点验证。

## 验证

使用 PHP 自带开发服务器（在 `txt/` 根目录）：

```bash
php -S 127.0.0.1:8765
```

访问 `http://127.0.0.1:8765/write.php`，粘贴并提交样例：

```text
  C:\\Users\\Administrator\\Desktop\\test.txt
https://example.com/a/b?q=1&v=2
  / \\ | & < > " ' [] {}   多个空格
{ "path": "C:\\\\data\\\\logs" }

纯英文 ABC123 🤖
```

浏览页面后点击一键复制，将复制结果与输入内容比较（包括空行和前后空格）。可另运行 `php tests/text_regression.php` 测试编码器/解码器。

## v1.2 提交故障修复

- **已修复管理员发布 / 关闭每日限额时的 HTTP 500**：旧代码在消息已写入后，继续读取未初始化的 `$fd`，PHP 8 会报 `ValueError: Path must not be empty`。这会使页面看起来提交失败，但消息已经保存；升级前先检查是否有重复留言。
- 普通访客仍按配置的每日限额计数；无计数文件时不再产生 `file_get_contents` 警告。
- 新建留言改成 AJAX 提交，服务器明确返回 `ok`、错误原因和跳转 URL；仅确认保存成功后才跳转，提交过程禁止重复点击。
- 网络中断、PHP 报错或写权限不足时，在编辑器内显示原因并保留输入内容。网络异常可能发生在已保存之后，先检查列表再重试。
- 保留旧浏览器的 iframe 后备提交方式；不改动原有数据库结构及历史记录。

### 补丁部署

只更新 `run.php`、`write.php`、`inc/main.js`、`inc/content.php`、`inc/modern.css` 和本文档。不要覆盖 `config.php`、`data`、`__temp__` 或 `inc/badword.php`。备份后覆盖，并强制刷新浏览器页面（Ctrl+F5 / Cmd+Shift+R）。

## v1.5.1 提交 500 修复

若原网站可以修改 `data/file.php` 和 `data/index.txt`，但 PHP 用户无法在 `data/` 内创建 `entry_meta.php`、`.th-meta.lock`、`.th-write.lock` 等文件，v1.5.0 会在保存元数据时返回 HTTP 500。v1.5.1 会在写入前检测并提示，不会将未发布文本写入旧数据文件。

首次启用 v1.5 的访问密码、有效期及编辑功能，必须确保 PHP 运行账户可以写入 `data/` 目录；不要将目录长期设置为任何用户都可写的 777。建议把目录属主/属组设置为网站 PHP 服务进程或使用受限 ACL。保留 `entry_meta.php` 和 `entry_meta_guard.php`，不要删除或公开这两个文件。


### v1.5.2 管理员登录、访问密码与分享

- 管理密钥登录及退出改为 PHP 服务器端 Cookie，登录表单不再依赖隐藏 iframe；登录密码被默认遮蔽。
- 访问密码至少 4 个 Unicode 字符；随机密码为 4 位小写字母/数字的组合。建议重要内容使用更长密码，并保留每个 IP/留言的尝试次数限制。
- 新建、更新访问密码后尝试自动复制含密码的分享链接。受保护留言的分享按钮要求输入当前访问密码验证。链接中的 `#key=` 仅存于浏览器片段，打开时自动填入解锁框。
- 忘记既有访问密码时，管理员无法查看其明文，只能编辑该留言重置密码并产生新的分享链接。
- 若登录后的页面仍显示旧布局，请清除旧脚本缓存并强制刷新。新代码不改变 `data/file.php`、`data/index.txt` 的旧数据布局。
