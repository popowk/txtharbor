## v1.5.6 管理员与访客密码认证修复

- 管理员会话文件如因旧权限或共享主机限制无法写入 `data/`，可退回到系统**私有 PHP 临时目录**，登录和退出仍使用独立浏览器令牌；新版登录成功后增加浏览器 Cookie 自检提示。
- 受保护留言改用单独 `THSESSID` 会话 Cookie，隔离同一域名其他 PHP 程序的 `PHPSESSID`。Session 自动选择私有临时存储，检测失败明确提示，不再假装密码错误。
- 修复手动输入正确密码后页面重新锁定的会话持久化问题；锁定计数及服务端权限校验保持不变。
- 原有留言、密码哈希和私密分享设置不改动。升级后旧浏览器的临时解锁状态可能需要重新输入一次密码。

## v1.5.4 会话与详情页修复

- 密码详情页重新适配浅色、深色和移动端，输入框不再被旧版通用 label 样式覆盖。
- 发布者的浏览器使用 HttpOnly 的 PHP 会话 Cookie 识别临时分享凭据，服务器会话保存最多 24 小时；复制带密码链接无需重复输入密码。密码不会放入 Cookie 或永久留言元数据中。
- 在其他浏览器或会话过期后，仍需输入一次访问密码；分享链接中的 #key 依旧会自动填入。
- 管理员改为每个浏览器独立的哈希令牌文件 `data/admin_sessions.php`，彼此不挤下线；退出只撤销本浏览器，旧版 manage Cookie 不再授予管理权限。升级后需要重新登录一次。
- 备份应包含 `data/admin_sessions.php`（如存在）与 `data/entry_meta.php`（留言保护元数据）。备用管理员认证和访客会话可能存放在 PHP 系统临时目录，不包含在网站代码更新包中。

## v1.5.3 紧急修复：提交、权限、更新一致性与界面

- 修复分享设置在深色主题中继承旧版 `label` 白底样式；到期时间仅在选中自定义后显示。
- 发布前检查 15 个运行组件是否与 `VERSION` 同版本；文件混用时明确返回 HTTP 503，不盲目写入留言数据。
- 发布错误日志增加失败阶段；没有密码也能正常发布。遇到无法复现的服务器错误可使用编号在 PHP 错误日志中查询具体文件、行号。
- 退出管理员时撤销服务端管理令牌，并清理历史 Cookie 路径。管理员页面强制禁用缓存，防止显示已退出的旧 UI。
- 管理设置与更新中心统一读取同一个 `VERSION` 文件；可检测关键组件不一致，同版本允许**修复安装**。
- 在线更新在写入后验证每个文件哈希，**最后才更新 VERSION**，并刷新 PHP OPcache；失败时恢复代码备份。
- 留言列表明确提供查看详情、分享、原文复制及管理员编辑/置顶入口。

**线上升级特别提醒**：部署后先备份原有 `config.php`、`data/` 与 `__temp__/`。若出现编号错误，先查看服务器 PHP 错误日志中 `TxtHarbor publish failed [编号]`，不要反复重复提交。若更新中心提示“运行文件版本不一致”，请执行修复安装或手动覆盖完整更新包，切勿直接改 VERSION 文字。

## v1.5.2 登录、密码分享与权限修复

- 修复管理员管理密钥登录和退出：改由服务器直接签发/清除 HttpOnly Cookie，使用正常页面跳转，不再依赖隐藏 iframe 的 JavaScript Cookie 回调；登录失败保留错误提示。
- 管理员登录框重新排版，管理密钥和后台的管理密码修改输入框均默认遮蔽为圆点。
- 访问密码最低 **4 个 Unicode 字符**（上限 128 字节）。发布与管理员编辑可点击“随机生成”得到 **4 位小写字母 + 数字**（至少含一种字母和一种数字）。四位密码较弱，敏感内容建议使用更长密码。
- 修复受保护留言的访问验证：当 `__temp__` 不可写时尝试系统私有临时目录/安全数据目录，明确区分验证服务故障与 15 分钟内的密码次数限制。
- 新发布/重新设置密码成功后尝试自动复制含密码的分享链接；分享按钮在生成带密码链接前验证输入密码。链接使用 `#key=...` 片段（不会随 HTTP 请求送入服务器），访问后自动填写解锁密码，但不会自行提交。
- 只保存密码哈希，不保存明文；**带密码的分享链接本身具有访问能力，请只发送给可信任的人**。若失去明文密码，管理员可以编辑留言重置密码后生成新链接。
- 新增 `tests/ui_regression.js`（Node.js 原生模块）测试密码生成与分享复制；原文、旧留言、升级结构保持兼容。

## v1.5.0 留言内容与分享升级

- **Markdown 自动识别**：常用标题、粗体、斜体、删除线、列表、引用、代码块和 HTTP(S) 链接安全预览；所有原文完整保留。渲染默认禁止 HTML、脚本和外链图片自动加载。可切换查看原文并一键复制原始 Markdown。
- **单条分享链接**：每条留言有 24 位固定标识 `entry.php?id=...`，分页、置顶、管理员编辑及新版管理员回复都不改变链接。删除后链接失效。
- **管理员编辑与置顶**：允许标题和正文编辑、单独置顶、取消置顶；新版管理员回复也写入元数据，不改变历史索引指针。
- **有效期**：发布时选择永久、1/7/30 天或自定义北京时间；到期后访客列表和详情均不展示（管理员仍可续期）。到期默认隐藏，不自动物理删除。
- **密码保护**：发布时或管理员编辑时设置/更换/移除访问密码。使用 `password_hash` 存储，未解锁不返回标题、正文、原始 Markdown 或复制内容；错误次数按 IP + 留言限制。
- **旧数据兼容**：原 `data/file.php` 与 `data/index.txt` 原封不动，扩展内容保存在 `data/entry_meta.php`，原文编辑为叠加数据。数据文件异常时拒绝公开内容（fail-closed）。
- **外部图片存储预留**：仅新增 `inc/media_store.php` 适配器合同、`docs/external-media.md` 设计说明及 `media` 元数据字段；**没有上传接口、图片预览或网盘绑定**，后续可以接 WebDAV、S3 兼容服务或网盘官方 API。

### 非常重要：升级与安全

1. 升级前完整备份 `config.php`、`data/` 和 `__temp__/`；**不要清空** `data/entry_meta.php`、`data/entry_meta_guard.php`，前者含访问密码的哈希及编辑后的内容。
2. 共享链接只在新版本创建后保证稳定；以前按文件指针创建的 `?focus=` 提交跳转仍兼容，但不是永久分享地址。
3. 在 Apache 上，`data/.htaccess` 会阻止 HTTP 直接访问数据目录；**Nginx 用户必须自行添加 `location ^~ /data/ { deny all; }` 与 `location ^~ /__temp__/ { deny all; }`** 并先核验现有站点根路径，以免数据库或临时文件被访问。
4. 图片网盘尚未接入；不可直接把含隐私内容的公共网盘链接粘进私密 Markdown（当前不会自动嵌入图片，但外部链接本身可能不受本站密码控制）。正式接入外部附件必须使用服务端授权或短期有效签名地址。
5. 提供常见 Markdown 语法的安全子集，不是完整 GFM；尤其不渲染原生 HTML 和远程图片，表格语法将按普通文本显示。

## 特性

- 简洁的浅色/深色科技风，默认跟随系统主题，也可在右上角手动切换并记住偏好；手机和桌面自适应。
- 编辑框一键清空、一键粘贴，正文一键复制。
- 支持纯英文、数字和特殊字符；保留 `/`、`\\`、`|`、多空格、制表符、换行等原文。
- 发表成功自动回到列表，定位并高亮刚刚发布的留言。
- 管理员留言管理：单条删除、勾选批量删除、内容审核、回复。
- 保留旧版 GB2312/GBK 文本数据库的字节索引；新版使用 UTF-8 包装以无损存储特殊字符。
- 后台 GitHub Release 更新中心：可配置仓库和镜像地址、直连/代理/自动切换，校验 SHA-256 后备份并安装。

## 从既有 162100 / TxtHarbor 站点升级

1. **完整备份网站，包括 `config.php`、`data/`、`inc/badword.php`。**
2. 下载 `txtharbor-update.zip`（Release 附件），把里面 `txt/` 的文件覆盖到网站对应目录。
3. **不要覆盖/删除** `config.php`、`data/`、`__temp__/` 和自定义禁词表 `inc/badword.php`。
4. 登录后台后打开 **留言管理**：`index.php?admin_run=1`，或进入 **版本更新**：`update.php`。
5. 建议部署 PHP 7.4+；在线升级需要 `ZipArchive`、HTTPS 出站访问和相应代码目录写权限；没有 ZipArchive 可手动覆盖。

> 严禁将旧 `data/file.php` 转码后重写；索引是基于文件的字节偏移，不是字符位置。

## 新安装（仅供代码测试和开发）

1. 把源代码放在 PHP 网站根目录，复制 `config.example.php` 为 `config.php`。
2. 在 `config.php` 把 `$web['password']` 修改为你的管理密码摘要；可以用 `php tools/hash_password.php` 生成。**不要把管理密码或生成后的 `config.php` 提交到 GitHub。**
3. 创建可写的 `data/` 和 `__temp__/`，初始化：

   ```sh
   mkdir -p data __temp__
   printf '<?php die(); ?>' > data/file.php
   : > data/index.txt
   : > data/space.txt
   ```

4. 浏览 `index.php`，从 `admin.php` 登录后设置站点内容及审核规则。建议启用 HTTPS，定期离线备份。

旧项目的验证码、权限和数据库设计比较古老，**不建议在对抗性公网生产环境中未经安全审计直接开放**。

## 发布 GitHub 更新

每次正式发布都更新根目录 `VERSION`（如 `1.5.0`），然后运行：

```sh
python3 tools/build_release.py
```

得到 `dist/txtharbor-update.zip`。推送到 `main` 时，仓库的 `.github/workflows/release.yml` 会根据 `VERSION` 自动创建对应 Tag 和正式 Release，并上传 `txtharbor-update.zip`（需要仓库允许 GitHub Actions 创建 Release）。也可以手动发布，Tag 要与版本对应（如 `v1.5.0`），附件名必须为 `txtharbor-update.zip`。

下载路径：

- GitHub: `https://github.com/popowk/txtharbor/releases/download/v1.5.0/txtharbor-update.zip`
- 国内代理: `https://git.wksite.cn/popowk/txtharbor/releases/download/v1.5.0/txtharbor-update.zip`

在线安装要求 GitHub API 对该 Release 附件提供 `digest: sha256:...` 字段，且校验通过，否则只能手动下载覆盖，以免上传错误或代理异常导致破坏。新版更新中心的地址都可以修改，用户不必依赖固定仓库名。

## 隐私与备份

- `config.php` 存储私有管理设置，`data/` 存储留言与管理员会话记录，`__temp__/` 存储临时操作数据；这些均通过 `.gitignore` 排除。
- GitHub 公开仓库中**不要上传**上述目录中的真实文件、运行日志、Cookie 或密码。
- 在线安装只替换白名单代码文件，旧代码备份保存到站点根目录之外的服务器临时目录。

## v1.5.6 · 编辑与自定义有效期修复

- 编辑保存改进：成功后复制链接或跳转的浏览器异常不会误报为“保存失败”，页面提供明确的服务器错误信息。
